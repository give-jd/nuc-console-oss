[dashboard] Console and rotation

The text console and the pages that take turns on a monitor with no keyboard (rotation, Details pages); the pace of every screen. A console that runs reads config.ini again when it starts.

sections attention, exposure, webapps, firewall, system, containers, databases, boot, network_traffic, sessions, tailscale, docker_disk, disks

The order of the overview's sections, first to last (the console, the classic web page, and the web shell's default preset). A section left out keeps its place at the end; one switched off under Screens and sections is not drawn. comma-separated: attention, exposure, webapps, firewall, system, containers, databases, boot, network_traffic, sessions, tailscale, docker_disk, disks · default: all, in this order

mode overview

The console: overview = one screen, no keyboard needed; rotate = three pages that take turns (the arrow keys move through them). overview | rotate · default overview

rotate_seconds 15

Seconds each page stays when pages take turns (rotate, the Details pages, a full-screen window); on the web shell's wall page, the seconds between two scrolls. 3-600 · default 15

refresh_seconds 2

Seconds between two redraws of every screen and page (a page's - / + links change it there for a while). Faster: livelier bars, a little more CPU. 1-10 · default 2

columns 0

The console's layout width in characters; 0 = the real console's. Set it when the monitor shows less than the console believes it has: the layout is never larger than the real console. 0 (automatic) or 40-500 · default 0

rows 0

The console's layout height in lines; 0 = the real console's. 0 (automatic) or 10-200 · default 0

spacing 1

1 = a blank line under each section title (more air, a few more rows); 0 = compact. The console and the classic web page. 0-1 · default 1

details yes

yes: a monitor with no keyboard turns to Details pages that show in full what the overview cut (… +N more), then comes back; no: the overview alone, never rotating. yes or no · default yes

overview_seconds 45

How long the overview stays before the Details pages (details = yes). 10-600 · default 45

map_in_rotation no

yes: the MAP screen, opened as far as it fits, joins the pages that take turns. yes or no · default no

cpu_in_rotation no

yes: the CPU screen joins the pages that take turns. yes or no · default no

health_in_rotation no

yes: the HEALTH screen joins the pages that take turns. yes or no · default no

[ui] Look and layout: everyone's defaults

What the console and every browser start with. A browser's own choices (Appearance, above) and ?ui= in a link come first; a key that is not set falls to the preset, then to the built-in default.

The web interface served: app = the shell of cards (this page); classic = the older text pages, kept for one release. app | classic · default app

theme not set

density not set

A ready-made layout, key figures and hidden cards: default; security (exposure and the firewall first); server (the system and the containers first); desktop (no containers, databases or web apps). layout, kpis and hidden below override it. default | security | server | desktop (or empty: not set) · default default

order not set

severity: a card that needs attention moves up; fixed: the cards keep the layout's order. On the console the cards keep their order unless this says severity. severity | fixed (or empty: not set) · default severity

[web] Web view (an installation's service)

The optional web service of an installation, the dashboard's only network listener. The desktop app and a portable run always serve 127.0.0.1 on a port of their own, without a token: they use the grid size and allowed_hosts only.

enabled no

yes: an installation runs the web view as a service (off by default). yes or no · default no

bind 127.0.0.1

The address it listens on. 127.0.0.1 = this machine only: publish it with tailscale serve or a reverse proxy. Any other address needs token_file, or the service refuses to start. default 127.0.0.1

port 8787

The TCP port it listens on (by default: http://127.0.0.1:8787). 1-65535 · default 8787

token_file not set

A file with a secret of 16 characters or more (mode 0600, readable by the nuc-console user): every request must carry it. Never write the token itself in config.ini.

allowed_hosts not set

Extra names in the Host header accepted when no token is set, comma-separated (a guard against DNS rebinding): localhost, 127.0.0.1, the bind address, the hostname and *.ts.net always are.

settings_actions yes

yes: the settings page of an installation may change the presentation keys (what config.ini says wins for every other key); no: it only shows, and what it chose before counts for nothing (an administrator's lock). yes or no · default yes · a lock: only config.ini changes it, never this page

columns 200

Width of the classic web pages' grid in characters (a page can ask ?cols=). 60-300 · default 200

rows 60

Height of that grid in lines. 20-120 · default 60

[expose] Intended reach of services

One per line, name or port = local | tailnet | lan | internet: the widest reach you intend. When the real reach is wider, ATTENTION raises over-exposed (the other alarms are never silenced by it). A name is a container, a compose service or project, a process, a systemd unit, a database name or kind, or a [webapps] name; a port is 8080 or 8080/udp. Several lines on one service: the most restrictive wins.
